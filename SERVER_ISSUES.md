# Обнаруженные проблемы в schedule_server.py

## 🔴 Критические проблемы

### 1. **Отсутствие поля `note_type` в схеме БД сервера**
**Проблема:** В клиенте есть поле `note_type` в таблице `schedules`, но на сервере его нет.

**Клиент (schedule_client.py:197):**
```sql
note_type TEXT,
```

**Сервер (schedule_server.py:272-282):**
```sql
-- note_type отсутствует!
```

**Последствия:**
- Потеря данных при синхронизации (типы примечаний не сохраняются)
- Несоответствие схем БД клиента и сервера
- Ошибки при работе с примечаниями

**Решение:** Добавить поле `note_type` в схему БД сервера и обновить все методы работы с расписанием.

---

### 2. **Отсутствие обработки `note_type` в методах сервера**
**Проблема:** Методы `get_schedule`, `save_schedule`, `sync_data` не обрабатывают поле `note_type`.

**Затронутые методы:**
- `get_schedule()` - не возвращает `note_type`
- `save_schedule()` - не сохраняет `note_type`
- `sync_data()` - не синхронизирует `note_type`

---

### 3. **Отсутствие поля `is_deleted` в таблице `employees` на сервере**
**Проблема:** Клиент использует мягкое удаление сотрудников (`is_deleted`), но сервер не поддерживает это поле.

**Последствия:**
- Удаленные сотрудники не синхронизируются корректно
- Невозможно восстановить удаленных сотрудников через сервер

---

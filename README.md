# Система управления расписанием

Клиент-серверное приложение для ведения расписания сотрудников в локальной
сети. Интерфейс и сообщения — на русском языке.

## Состав проекта

| Файл | Назначение |
| --- | --- |
| `schedule_client.py` | клиент: таблицы месяцев, примечания, экспорт в Excel, офлайн-очередь |
| `schedule_server.py` | сервер: SQLite, сетевой протокол, управление сотрудниками и периодами |
| `schedule_common.py` | общие функции: периоды, календарь, часы, пути, логи, протокол |
| `tests/test_common.py` | тесты общих функций и миграции периодов |

## Требования

- Python 3.9+
- PyQt5
- openpyxl

Установка зависимостей:

```bash
pip install -r requirements.txt
```

Для работы приложения достаточно `PyQt5` и `openpyxl`; PyInstaller нужен
только для сборки `.exe`.

## Запуск

Сначала запустите сервер:

```bash
python schedule_server.py
```

Затем клиент:

```bash
python schedule_client.py
```

По умолчанию сервер слушает порт `8888`. Адрес и порт задаются в настройках
подключения клиента.

## Рабочий день

Стандартная смена — с `07:30` до `20:00`, то есть 12,5 часа. Время окончания
можно изменить в примечании к ячейке; отработанные часы пересчитываются от
`07:30`. Для нерабочих статусов часы равны нулю.

## Данные и логи

- Если рядом со скриптом (или `.exe`) уже есть `local_schedule.db` /
  `schedule_server.db`, используется он — это сохраняет совместимость со
  старыми установками.
- Иначе базы создаются в `%APPDATA%\WorkSchedule`.
- Логи с ротацией пишутся в `%APPDATA%\WorkSchedule\logs`.

Названия периодов автоматически приводятся к единому виду
`Месяц Год (вариант)`. Старые записи вида `2026-01` мигрируют при запуске
клиента и сервера; при совпадении данные объединяются.

## Синхронизация

- Все сообщения передаются с 4-байтовым префиксом длины, поэтому размер
  ответа не ограничен одним `recv`.
- Если сервер недоступен, изменения сотрудников и расписания сохраняются
  локально и попадают в очередь. При восстановлении связи очередь
  отправляется автоматически; повторные изменения одного объекта
  схлопываются.
- Старые очереди, содержавшие read-запросы, очищаются при запуске клиента.
- Сервер является источником истины для списка сотрудников, должностей и
  порядка в периоде.

## Сборка

```bat
setup_client.bat
setup_server.bat
```

Готовые файлы появятся в `dist\`.

## Тесты

```bash
python -m unittest discover -s tests -v
```

## Ограничения

Сетевые запросы клиента выполняются синхронно в потоке интерфейса. На
локальной сети это обычно незаметно, но при медленном соединении или очень
большой базе интерфейс может кратковременно подвисать. Полный перенос сети в
фоновый поток — отдельная задача, требующая переработки UI-слоя.
